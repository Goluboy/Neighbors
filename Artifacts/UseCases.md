# Сервис обмена вещами между соседями
## Спецификация Use Cases (v3)

### Принятые решения

1. **Верификация при регистрации — по номеру телефона, вход — по телефону и паролю.** Геолокация и инвайт-ссылки для проверки проживания не используются.
2. **Точка проживания не верифицируется.** Пользователь сам указывает свой дом (адрес или точка на карте). Система хранит точку и использует её для выдачи, но не проверяет подлинность.
3. **Локальная выдача с расширением на город.** По умолчанию — вещи в шаговой доступности от точки. Если локальная выдача пуста либо пользователь явно расширил поиск — показывается выдача по всему городу.
4. **Платформа — веб-сайт** (не приложение). Интерфейс адаптивный, работает в браузере на десктопе и мобильном.
---

### Акторы

| Актор | Описание |
|---|---|
| **Гость** | Пользователь без аккаунта. |
| **Арендатор** | Пользователь, берущий вещь в аренду. |
| **Владелец** | Пользователь, сдающий свою вещь. |
| **Система** | Веб-сервис: витрина, чат, залоги, уведомления, статусы. |
| **Модератор** | Администратор: разбор споров, блокировки, модерация контента. |

---

### Границы (Scope)

- Обмен вещами между жителями в шаговой доступности; встреча — только лично, доставки нет.
- Размещаются только физические предметы. Услуги, еда и медикаменты запрещены [1].
- Телефонные номера не раскрываются — коммуникация только во внутреннем чате [1].
- Платформа не взимает плату за размещение и комиссию со сделки [1].

---

### Глоссарий

| Термин | Определение |
|---|---|
| Точка проживания | Координаты дома, указанные пользователем самостоятельно. |
| Локальная выдача | Объявления владельцев, чьи точки в пределах радиуса шаговой доступности от точки пользователя. |
| Расширенная выдача | Объявления по всему городу (fallback и опция). |
| Залог | Сумма, замораживаемая на виртуальном балансе Арендатора до возврата вещи. |
| Холдирование | Временная заморозка залога без списания. |
| Забронирована | Статус вещи между созданием заявки и её одобрением/отменой — вещь недоступна другим. |
| Спорная ситуация | Статус заказа, при котором разморозка залога заблокирована и подключён Модератор. |

## UC-1: Регистрация с подтверждением номера и вход по паролю

**Краткое описание:** Гость создаёт аккаунт: подтверждает номер телефона кодом из SMS и задаёт пароль. Дальнейший вход выполняется по номеру телефона и паролю; SMS-код нужен только при регистрации и восстановлении пароля.

**Основной актор:** Гость. (Второстепенный актор: Система)

**Предусловия:**
- У Гостя есть активный номер телефона.
- Гость открыл веб-сайт.

**Основной сценарий:**
1. Гость вводит номер телефона.
2. Система отправляет SMS-код подтверждения.
3. Гость вводит код.
4. Гость задаёт пароль.
5. Система проверяет код, создаёт аккаунт со статусом «Активен» и сохраняет хэш пароля.
6. Гость получает доступ к витрине.

**Бизнес-правила:**
- Подтверждение номера обязательно только при регистрации; повторный вход — по телефону и паролю, без SMS.
- Пароль хранится только в виде хэша; минимальная длина — 8 символов.
- Код одноразовый, имеет срок жизни и ограниченное число попыток ввода; повторная отправка ограничена таймаутом.
- Попытка зарегистрировать уже существующий номер не создаёт дубль: система сообщает, что аккаунт существует, и предлагает войти.
- Геолокация для верификации не используется.

**Альтернативные сценарии:**
- **Неверный код:** Система сообщает об ошибке и предлагает ввести код заново; после исчерпания попыток — повторная отправка кода.
- **Код истёк:** Система предлагает отправить новый код.
- **Неверный пароль при входе:** Система сообщает об ошибке; после нескольких неудачных попыток вход временно блокируется.
- **Забыл пароль:** Пользователь восстанавливает пароль по коду из SMS (запрос кода с назначением «сброс пароля»).

## UC-2: Указание точки проживания

**Краткое описание:** Пользователь указывает свой дом (адрес или точка на карте). Система сохраняет точку и использует её как центр локальной выдачи.

**Основной актор:** Пользователь. (Второстепенный актор: Система)

**Предусловия:**
- Аккаунт подтверждён (UC-1).

**Основной сценарий:**
1. Пользователь указывает свой дом (ввод адреса или выбор точки на карте).
2. Система сохраняет координаты как «моя точка проживания».
3. Локальная выдача строится от этой точки.

**Бизнес-правила:**
- Точка не верифицируется — это заявленное пользователем место проживания.
- Точка может быть изменена в любой момент; выдача пересчитывается от новой точки.
- Без указанной точки доступна только расширенная выдача (весь город).
- Точка проживания не раскрывается другим пользователям — в выдаче видно только расстояние, не адрес.

**Альтернативные сценарии:**
- **Изменение точки:** Пользователь меняет точку из профиля; прежние заказы не затрагиваются.
- **Отказ от указания точки:** Пользователь продолжает пользоваться сервисом, но видит только расширенную выдачу.

## UC-3: Поиск вещи и запрос бронирования

**Краткое описание:** Арендатор находит нужную вещь в витрине, изучает условия и отправляет Владельцу запрос, подтверждая готовность заморозить залог (если он ненулевой) на своём балансе.

**Основной актор:** Арендатор. (Второстепенный актор: Система)

**Предусловия:**
- Аккаунт подтверждён (UC-1).
- К профилю привязан виртуальный баланс с достаточным остатком (только если залог вещи > 0).
- Выбранная вещь свободна.

**Основной сценарий:**
1. Арендатор открывает витрину: по умолчанию — локальная выдача (вещи в шаговой доступности от его точки).
2. Если локальная выдача пуста, система показывает расширенную выдачу (весь город) с явным указанием, что вещи вне шаговой доступности.
3. Арендатор находит вещь через рубрикатор (категории «Ремонт», «Уборка», «Отдых», «Дети» [1]) или поиск.
4. Открывает карточку вещи: фото, описание, залог, условия, рейтинг Владельца, расстояние до точки Владельца.
5. Нажимает «Запросить аренду».
6. Если залог > 0 — система показывает поп-ап о заморозке залога; Арендатор подтверждает.
7. Система холдирует залог на балансе Арендатора (при ненулевом залоге).
8. Статус вещи меняется на «Забронирована»; статус заказа — «Ожидает подтверждения».
9. Владельцу отправляется уведомление о новой заявке.

**Бизнес-правила:**
- При ненулевом залоге запрос Владельцу не отправляется без успешного холдирования [1]; при нулевом залоге шаг холда пропускается.
- Холдирование — заморозка, а не списание средств [1].
- Арендатор не может бронировать собственную вещь.
- На время «Ожидает подтверждения» вещь переходит в «Забронирована» — другие арендаторы не могут её запросить.
- Весь город показывается в двух случаях: локальная выдача пуста (fallback) или пользователь явно расширил поиск.

**Альтернативные сценарии:**
- **Недостаточно средств:** На шаге 7 холдирование отклоняется. Система сообщает об ошибке и предлагает пополнить баланс; сделка отменяется, статус вещи возвращается в «Свободна» [1].
- **Вещь уже занята:** На момент запроса вещь уже «Забронирована» (кто-то запросил раньше). Система сообщает об этом и предлагает похожие вещи в выдаче.
- **Отмена заявки Арендатором:** Арендатор передумал до ответа Владельца и отменяет заявку. Система размораживает залог (если был) и возвращает вещь в «Свободна». На рейтинг не влияет.
- **Расширение поиска явно:** Пользователь сам переключает выдачу на «весь город», если хочет найти редкую вещь за пределами района.
- **Вопрос до бронирования:** Арендатор хочет уточнить детали, не замораживая залог. Нажимает «Задать вопрос» — Владельцу уходит запрос на ответ без создания заказа и без холда (см. Открытый вопрос 7).

## UC-4: Коммуникация, встреча и старт аренды

**Краткое описание:** Владелец одобряет запрос, стороны договариваются о встрече во внутреннем чате, Арендатор забирает вещь и подтверждает получение.

**Основной актор:** Арендатор, Владелец. (Второстепенный актор: Система)

**Предусловия:**
- Заявка в статусе «Ожидает подтверждения», залог (если ненулевой) захолдирован.

**Основной сценарий:**
1. Владелец открывает заявку и нажимает «Одобрить».
2. Система создаёт защищённый внутренний чат между сторонами [1].
3. Стороны договариваются о времени и месте встречи (например, у подъезда или в холле [1]).
4. Происходит личная встреча; Арендатор осматривает вещь [1].
5. Арендатор нажимает на сайте «Вещь у меня, всё отлично» [1].
6. Система запускает таймер аренды и переводит заказ в статус «В аренде» [1].

**Бизнес-правила:**
- Обмен сообщениями — строго внутри платформы, номера телефонов не раскрываются [1].
- Доставки нет — встреча только лично [1].
- Таймер аренды запускается подтверждением получения на сайте.

**Альтернативные сценарии:**
- **Отказ Владельца:** Владелец нажимает «Отклонить» или не отвечает в течение установленного срока. Система отменяет заказ, размораживает залог и возвращает вещь в «Свободна» [1].
- **Отказ при осмотре:** Арендатор обнаруживает, что вещь не соответствует описанию, и нажимает «Отказаться от аренды». Залог размораживается, сделка аннулируется без влияния на рейтинги [1].
- **Отмена Арендатором после одобрения, до встречи:** Арендатор передумал. Залог размораживается, вещь в «Свободна». Влияние на рейтинг — на усмотрение (см. Открытый вопрос 8).

## UC-5: Возврат вещи, разморозка залога и оценка

**Краткое описание:** Арендатор возвращает вещь, Владелец подтверждает состояние, система размораживает залог, стороны оценивают друг друга.

**Основной актор:** Владелец, Арендатор. (Второстепенный актор: Система)

**Предусловия:**
- Заказ в статусе «В аренде».

**Основной сценарий:**
1. Арендатор нажимает «Инициировать возврат».
2. Система уведомляет Владельца о готовности вернуть вещь.
3. Стороны встречаются; Владелец забирает и осматривает вещь.
4. Владелец нажимает «Вещь получена без повреждений» [1].
5. Система размораживает залог (если был) и закрывает финансовую часть сделки [1].
6. Обеим сторонам показывается окно оценки: 1–5 звёзд и краткий отзыв [1].
7. Система обновляет рейтинги сторон; заказ переносится в «Историю операций».

**Бизнес-правила:**
- Рейтинг пользователя — среднее из полученных оценок; показывается вместе с числом оценок.
- Оценки не публикуются одной стороне, пока не поставлена встречная оценка (или не истёк отведённый срок), — защита от «предвзятой мести».
- Если сторона не поставила оценку в течение отведённого срока (например, 3 дня), заказ всё равно завершается; оценка «пропускается» и на рейтинг не влияет.

**Альтернативные сценарии:**
- **Порча вещи:** Владелец обнаруживает поломку и нажимает «Сообщить о проблеме» [1]. Система блокирует разморозку залога, переводит заказ в «Спорная ситуация» и подключает Модератора (см. UC-9).
- **Просрочка возврата:** Срок аренды истёк, вещь не возвращена. Система отправляет напоминания Арендатору; после повторного истечения срока (или по кнопке Владельца) заказ переводится в «Спорная ситуация». Разморозка залога заблокирована (см. UC-9).

## UC-6: Публикация объявления

**Краткое описание:** Владелец размещает свою вещь в каталоге, заполняя карточку с фотографиями и условиями.

**Основной актор:** Владелец. (Второстепенный актор: Система)

**Предусловия:**
- Аккаунт подтверждён (UC-1), у Владельца указана точка проживания (UC-2).
- У Владельца есть физический предмет, не входящий в список запрещённых.

**Основной сценарий:**
1. Владелец нажимает «Добавить вещь».
2. Загружает фотографии (включая фиксацию текущих дефектов).
3. Вводит название и описание.
4. Выбирает категорию из рубрикатора.
5. Указывает условия: размер возвратного залога (может быть 0) и формат (бесплатно / бартер / деньги).
6. Нажимает «Опубликовать».
7. Система сохраняет карточку со статусом «Свободна» и отображает её в витрине.

**Бизнес-правила:**
- Допускаются только физические предметы; услуги, еда и медикаменты запрещены [1].
- Объявление попадает в локальные выдачи пользователей, чьи точки в шаговой доступности от точки Владельца; в расширенной выдаче (весь город) оно тоже доступно.
- Платформа не взимает плату за размещение и комиссию со сделки [1].

**Альтернативные сценарии:**
- **Нарушение правил публикации:** Система (по стоп-словам) или Модератор обнаруживает запрещённый товар. Публикация блокируется, Владельцу приходит уведомление с пояснением правил [1].
- **Временное скрытие:** Владелец скрывает вещь из каталога («Недоступна»). Вещь исчезает из выдачи до повторной активации; активные заказы по ней продолжают выполняться [1].

## UC-7: Управление профилем и балансом

**Краткое описание:** Пользователь управляет своими данными, точкой проживания, виртуальным балансом и историей операций.

**Основной актор:** Пользователь. (Второстепенный актор: Система)

**Предусловия:**
- Аккаунт подтверждён (UC-1).

**Основной сценарий:**
1. Пользователь открывает профиль.
2. Редактирует имя, аватар, описание и точку проживания.
3. Пополняет виртуальный баланс (учебная заглушка) или проверяет остаток.
4. Просматривает историю операций: заказы, статусы, суммы залогов, оценки.

**Бизнес-правила:**
- Смена точки проживания пересчитывает локальную выдачу без влияния на активные заказы.
- История операций доступна только самому пользователю.

## UC-8: Уведомления

**Краткое описание:** Система информирует пользователя о событиях его заказов; пользователь управляет тем, какие уведомления получать.

**Основной актор:** Пользователь, Система.

**Основной сценарий:**
1. Система отправляет уведомления: новая заявка, одобрение/отклонение, сообщение в чате, напоминание о старте/возврате, статус спора.
2. Пользователь настраивает типы уведомлений в профиле.

**Бизнес-правила:**
- Настройки применяются к новым событиям.
- На веб-сайте используются внутренние уведомления (лента на сайте) и браузерные уведомления/email-заглушка в учебной версии.

## UC-9: Администрирование и модерация споров

**Краткое описание:** Модератор разбирает спорные ситуации, принимает решение по залогу и управляет блокировками.

**Основной актор:** Модератор. (Второстепенный актор: Система)

**Предусловия:**
- Модератор авторизован с ролью администратора.

**Основной сценарий:**
1. Заказ переводится в «Спорная ситуация» (порча вещи, просрочка возврата, жалоба стороны).
2. Модератор получает заявку на разбор.
3. Изучает контекст: переписку чата, историю заказа, карточку вещи, заявленную проблему.
4. Принимает решение:
   - разморозить залог в пользу Арендатора (вещь вернули, претензия снята);
   - списать залог в пользу Владельца (вещь повреждена/не возвращена);
   - отклонить жалобу;
   - дополнительно заблокировать пользователя.
5. Система применяет решение: переводит заказ в «Завершён» или «Отменён», выполняет действие с залогом, уведомляет стороны.
6. Обе стороны видят решение и его обоснование.

**Бизнес-правила:**
- Из статуса «Спорная ситуация» заказ переводится только решением Модератора.
- Блокировка пользователя приостанавливает возможность публиковать и брать вещи; причина блокировки видна пользователю.

## UC-10: Жалоба на контент

**Краткое описание:** Пользователь жалуется на объявление, сообщение или другого пользователя; Модератор рассматривает жалобу.

**Основной актор:** Пользователь, Модератор. (Второстепенный актор: Система)

**Основной сценарий:**
1. Пользователь нажимает «Пожаловаться» на объявлении, сообщении или профиле.
2. Указывает причину и отправляет жалобу.
3. Система передаёт жалобу Модератору и временно помечает цель жалобы.
4. Модератор рассматривает: скрывает объявление, удаляет сообщение или отклоняет жалобу; при повторных нарушениях — блокирует пользователя.
5. Система уведомляет автора жалобы о результате (без раскрытия действий модератора против другого пользователя).

**Бизнес-правила:**
- Жалоба видна Модератору с указанием автора, но автор жалобы скрыт от целевого пользователя.
